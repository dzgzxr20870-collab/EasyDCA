## 1. Summary

`migration 044` (Backfill สินทรัพย์ทุกแถวให้สังกัดพอร์ต) **จะทำให้ระบบพัง 4 จุด
พร้อมกันทันทีที่ Apply** โดยที่จุดที่ร้ายแรงที่สุด **พังแบบเงียบสนิทและแตะเงินจริง**

| | รายละเอียด |
|---|---|
| ต้นตอ | `resolveOwnedAsset` มี Default Parameter `portfolioId = null` และ Caller ทุกตัวเขียน `params.portfolioId ?? null` ตามกันหมด → `portfolioId` เป็น `null` เสมอ |
| ตัวจุดชนวน | `044` Backfill ทำให้ **ไม่เหลือแถวที่ `portfolio_id IS NULL` อีกเลย** |
| ผลลัพธ์ | `.is('portfolio_id', null)` คืน `[]` เสมอ → **หาสินทรัพย์เดิมไม่เจอทุกครั้ง** |
| จับได้เมื่อไหร่ | ตอนรีวิวโค้ด 24 ส.ค. 2569 (ระหว่างหาที่วางด่าน Entitlement) **ก่อน Apply** |

## 3. Root Cause

### 3.1 ต้นตอเดียว กระจายด้วย Copy-paste

```js
// assetResolution.service.js:62 (เดิม) — ต้นตอ
async function resolveOwnedAsset(userId, symbol, { portfolioId = null, brokerId } = {}) {
                                                              // ↑ Default นี้คือจุดเริ่ม
```

แล้ว Caller ทุกตัวก็เขียนตามกันหมด:

| ไฟล์ | โค้ดเดิม |
|---|---|
| `transaction.service.js` (validateBuy) | `const portfolioId = params.portfolioId ?? null;` |
| `transaction.service.js` (processBuyCommand) | เหมือนกัน |
| `transaction.service.js` (validateSell) | เหมือนกัน |
| `profit.service.js` | `getAssetProfit(..., portfolioId = null, ...)` |
| `webhook.controller.js` | `const portfolioId = parsed.params.portfolioId ?? null;` |

ปลายทาง:

```js
// asset.repository.js:75 (เดิม) — ternary 2 ทางที่ยุบ undefined กับ null เข้าด้วยกัน
return portfolioId ? base.eq('portfolio_id', portfolioId) : base.is('portfolio_id', null);
```

### 3.2 ทำไมมันไม่พังมาก่อนหน้านี้

**ก่อน `044` ข้อมูลจริงบน Production มี `portfolio_id = NULL` แทบ 100%**
(`migration 014` บอกไว้เองว่า *"Free-tier ไม่มี portfolio"*) → `.is('portfolio_id', null)`
บังเอิญตรงกับข้อมูลทุกแถวพอดี โค้ดจึงทำงานถูกมาตลอด **ด้วยความบังเอิญ ไม่ใช่ด้วยการออกแบบ**

`044` คือตัวที่ทำลายความบังเอิญนั้น

## 4. ⭐ บทเรียนที่มีค่ากว่าตัวบั๊ก — คำเตือนที่ครอบไม่ครบ

`assetResolution.service.js` **มีคำเตือนเรื่องนี้เขียนไว้เองอยู่แล้ว** ตั้งแต่ Stage 5:

> *"⚠️ ห้ามเขียน `brokerId: params.brokerId ?? null` ที่จุดใดก็ตามก่อนส่งเข้ามา —
> การทำแบบนั้นเปลี่ยน 'ยังไม่ได้ถาม' ให้กลายเป็น 'ตอบแล้วว่าไม่มีโบรก' เงียบๆ …
> → ประวัติแตกคนละ `asset_id` = บั๊กเดียวกับที่ migration 014 เคยแก้เป๊ะ"*

**แล้วโค้ดในไฟล์เดียวกันนั้นก็ไปทำผิดแบบเดียวกันเป๊ะกับ `portfolioId`** —
รวมถึง Default Parameter ที่อยู่ห่างจากคำเตือนไปแค่ 30 บรรทัด

### กฎที่ได้จากเรื่องนี้

> **คำเตือนที่ครอบไม่ครบ อันตรายกว่าไม่มีคำเตือน**
>
> เพราะคนอ่าน (รวมทั้ง AI) เห็นว่า *"มีคำเตือนเรื่องนี้อยู่แล้ว"* จึงสรุปว่า
> **"ตรวจแล้ว"** และไม่เอะใจกับมิติที่คำเตือนไม่ได้พูดถึง — ถ้าไม่มีคำเตือนเลย
> อย่างน้อยคนอ่านยังต้องคิดเองทุกมิติ

**สิ่งที่ทำ:** ขยายคำเตือนให้ครอบทั้ง `brokerId` และ `portfolioId` พร้อมเขียนกำกับว่า
**ถ้าเพิ่มมิติที่ 3 ในอนาคต (เช่น sub-account) ต้องมาขยายคำเตือนนี้ด้วยเสมอ**

## 5. ⭐ ทำไมเทสต์ 2,624 ตัวจับไม่ได้เลยแม้แต่ตัวเดียว

**เพราะทุก Fixture จำลอง "โลกก่อน 044"**

สินทรัพย์ในเทสต์ทุกไฟล์ไม่มี `portfolioId` หรือเป็น `null` — ซึ่งตรงกับที่โค้ดค้นหาพอดี
เทสต์จึงเขียวสนิททั้งที่บั๊กมีอยู่จริง **เทสต์ไม่ได้ผิด มันแค่ทดสอบโลกที่กำลังจะไม่มีอยู่**

> **กฎ: Migration ที่เปลี่ยนรูปร่างข้อมูลเดิม ต้องมาพร้อม Fixture ของ "โลกหลัง
> Migration" เสมอ** — ไม่งั้นชุดเทสต์ทั้งชุดจะยืนยันแค่ว่า "โค้ดยังทำงานกับข้อมูล
> แบบเก่าได้" ซึ่งเป็นคำถามที่กำลังจะหมดความหมาย

### 5.1 บทเรียนซ้อน — Mock ที่รอยต่อ (ซ้ำรอย POSTMORTEM_AMOUNT_CONSISTENCY)

ตอนเขียน `portfolioResolution.regression.test.js` เสร็จใหม่ๆ ลองทำ Red-Green ด้วยการ

**นี่คือบทเรียนเดียวกับ `POSTMORTEM_AMOUNT_CONSISTENCY` เป๊ะ** — บั๊กอยู่ที่ "รอยต่อ"

## 6. Fix

ทำให้ `portfolioId` ใช้กติกาเดียวกับ `brokerId` ที่มีอยู่แล้ว (**ไม่ใช่ Pattern ใหม่**):

| ค่า | ความหมาย | พฤติกรรม |
|---|---|---|
| `undefined` | "ยังไม่ระบุ / พอร์ตไหนก็ได้" | ไม่กรอง `portfolio_id` เลย |
| `null` | "เจาะจงว่าไม่มีพอร์ต" | `.is('portfolio_id', null)` |
| `'<uuid>'` | เจาะจงพอร์ตนั้น | `.eq('portfolio_id', uuid)` |

1. `asset.repository.findAllByUserAndSymbol` — แยก 3 ทาง (เลิก ternary 2 ทาง)
2. `assetResolution.resolveOwnedAsset` — **ลบ Default `= null`** ออก
3. ลบ `?? null` ของ `portfolioId` ทุกจุด (`transaction.service` ×3 · `webhook.controller`)
4. `profit.service.getAssetProfit` — ลบ Default `= null`
5. เพิ่ม `AMBIGUOUS_ASSET_PORTFOLIO` — ถือ Symbol เดียวกันหลายพอร์ตแล้วไม่ระบุ
   → **ถาม/Reject ห้ามเดา** (กฎยืนข้อ 11) · ตรวจมิติพอร์ต **ก่อน** มิติโบรกเสมอ
6. สินทรัพย์ **ใหม่** ที่ไม่ระบุพอร์ต → ลงพอร์ต `is_default`
   (Invariant `044/045`: สินทรัพย์ทุกแถวต้องสังกัดพอร์ต)
7. ขยายคำเตือนใน Header ให้ครอบทั้งสองมิติ (ดู § 4)
